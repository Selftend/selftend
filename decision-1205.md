
- [The picker sheet's web keyboard and screen-reader contract](https://github.com/Selftend/selftend/issues/1205) — measured on a **real modal**, and it inverts the ticket: ✅ **react-native-web already gives Escape-closes, the focus trap, AND focus-return-to-opener for free** (verified on all three close paths — Escape, `Done`, backdrop), so `PickerSheet` must **not** hand-roll focus and must **not** copy `useModalPanelKeyboard`. ☠️ But the grid is unusable: the tab cycle is **36 stops** (backdrop → 4 chrome → **30 individual days** → Clear → Done), **no arrow key moves focus at all**, `aria-label` is the **bare day number** ("8, button"), there is **no `aria-selected`/`aria-pressed`/`aria-current`** so selection is **colour-only** (WCAG 1.4.1 + 4.1.2), there are **zero grid roles and no `aria-live`**, and ☠️ **`Prev`/`Next` are hardcoded English even in Bulgarian**. ☠️ **Focus on open lands on the invisible backdrop** ("Close, button") and ☠️ **`tabIndex: -1` does NOT keep it out of the cycle — it is stop 37**, because RNW's trap wraps via `focusFirstDescendant` and a `-1` element is still programmatically focusable. ☠️ **`components.Day` cannot fix any of it** — the library wraps it in its own `Pressable` with the label hardcoded — so the only lever is **`patch-package`** (precedent: `patches/react-native-sortables+1.9.4.patch`; ⚠️ the filename pins the version, so an upgrade silently drops it). Four rulings: **(1) patch + roving focus** → grid becomes **one tab stop** (36 → 7) with APG keys (`←/→` ±1 day, `↑/↓` ±7, Home/End week, PageUp/Down month, Enter selects) that move **focus only, never selection**; **(2) focus on open = the selected day**, today when unset; **(3) the backdrop leaves the focus path entirely** — `aria-hidden`, non-focusable, label removed, `Clear`/`Done` are #1160's visible way out; **(4) the time control uses composed names and NEVER auto-advances**. ☠️ **Premise corrections:** the ticket's opening claim is **false for the date half** — today's `<input type="date">` is **`aria-hidden`, `tabIndex: -1`, 1×1px**, so we never had an accessible date input, only the browser popup's post-activation a11y; ☠️ **`useRovingFocus` cannot be reused verbatim** (it is 1-D — `ArrowDown` = `ArrowRight` ±1, no PageUp/Down — and it **activates on every move**, which would fire ~30 draft changes across a month and make `aria-selected` follow focus); and the WCAG 2.5.3 finding the ticket cites as #1173 is actually on **#1172**. ⚠️ Patch surface is small: `components` is already threaded into every `Day`, so it is one optional `components.dayProps(day)` spread onto **both** `Pressable` branches. ☠️ **Nothing in `test/` gates any of this** (#1172 established there is no a11y check in the suite), so all of the above ships green today — the spec names explicit rendered assertions instead.
