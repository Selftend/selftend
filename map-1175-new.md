## Destination

A **spec** for date and time entry across the app: on web no browser-native widget ever appears, every date/time picker is the app's own themed sheet, and the two "Target date (optional)" fields (CBT goal, ACT committed action) get a real calendar instead of the browser popup / a free-text box. Handed to `/to-tickets` when the way is clear — this map decides, it does not build.

## Notes

- Domain: `src/components/app/date-field.tsx`, `date-time-field.tsx`, `date-range-field.tsx`, `time-field.tsx` + `time-field.web.tsx`; call sites `app/(app)/modules/cbt/goals/new.tsx` and `src/features/act/act-committed-action-new-screen.tsx`.
- Skills every session should consult: `/grilling`, `/domain-modeling`. `/prototype` for the appearance ticket.

**Rulings taken by the owner while charting (2026-08-20) — treat as settled:**

1. **Platforms:** all. The goal target date gets the in-app calendar on iOS/Android too, not just web.
2. **Scope:** four surfaces — CBT goal target date, ACT committed-action target date, the web `<input type="time">` fields, and the check-in calendar's English-only locale bug.
3. **Range for target dates:** today and future only. Past days render disabled.
4. **The rule:** *on web a browser widget must never appear.* Native **keeps** its OS pickers where they already exist (`TimeField` → `@react-native-community/datetimepicker`) and gains the in-app calendar only where there is no picker at all today.
5. **Structure:** extract **one shared picker sheet** primitive. `DateTimeField` / `DateRangeField` / the new date field become thin modes on it.
6. **Commit semantics:** **draft until Done**; dismissing (backdrop tap / Escape) discards. This changes shipped check-in behaviour, which commits live today.
7. **Typed entry:** calendar only, no keyboard typing of a date. The spec must acknowledge this as a deliberate speed/accessibility regression on web.
8. **Destination shape:** a spec, not a build.

**Premise checks — five of the ask's premises did not hold:**

- ☠️ **The check-in calendar cannot be reused verbatim.** `DateTimeField` hard-clamps `maxDate` to *now* (it exists to log past entries). A target date is inherently future — copied as-is, every valid date would be unselectable. It also always shows a time picker, takes a required ISO instant rather than a nullable `YYYY-MM-DD`, and has **no Clear**.
- ☠️ **`DateField` has exactly one call site** (the CBT goals wizard). This is not a sweep.
- ☠️ **On native that same field is a bare text box** where the user types `YYYY-MM-DD`. The complaint was framed as a web problem; the native path is worse.
- ☠️ **ACT's target date has zero validation** — free `Textarea` text goes straight into a Postgres `DATE` column, so typing "next Tuesday" fails the whole save with a generic error. Checked: the column rejects invalid text, so **no bad data exists and no migration is needed**.
- ☠️ **The check-in calendar is English even in Bulgarian.** `DateTimeField` never passes `locale`, and `react-native-ui-datepicker` defaults to `'en'`.
- ☠️ **Native `TimeField` uses the OS picker on purpose** (iOS spinner in a modal, Android's OS dialog). "No native widget everywhere" would have torn out a deliberate, correct affordance — hence ruling 4.

**Corrected by #1183** — one of the above was itself half wrong: the picker library imports **all ~45 dayjs locale bundles unconditionally, `bg` included**, so nothing needs importing and the bundle cost is already paid. `DateRangeField`, which passes `locale`, is therefore **already correctly localized**; only `DateTimeField` is English, from **one missing prop**. See the ticket for the rest.

## Decisions so far

- [Research: react-native-ui-datepicker v3 — time-only mode, locale mechanics, week start](https://github.com/Selftend/selftend/issues/1183) — a **time-only picker is reachable** (`initialView: "time"` + `hideHeader` + `mode: "single"`), so ruling 4 is achievable for the web time field without leaving the library. The locale fix is **two props** (`locale`, `firstDayOfWeek` — the latter is *not* locale-derived and hard-defaults to Sunday), costs zero bundle bytes, and `DateRangeField` already has half of it. `dayjs.locale()` is a **global mutation on every picker render**, but inert here because all user-facing formatting uses `Intl` — a constraint to write into the spec. `use12Hours` defaults to 24-hour and already contradicts the 12-hour `Intl` text beside it on the same screen.
- [What the target-date field looks like, closed and open](https://github.com/Selftend/selftend/issues/1184) — **boxed trigger with no X** (a clear button that appears and disappears makes the field change width), so clearing moves into the sheet as a **quiet `Clear` left, filled `Done` right** footer — which means the footer is **mode-dependent** and needs a low-emphasis button style the sheet does not have. Past days are disabled per ruling 3 and **outside days are hidden** (`showOutsideDays: false`), because otherwise the grid opens with eleven identical greys spanning two months. Unset reads **"No date set"** from a new shared key, retiring the borrowed `dateBar.selectDate` and **deleting** ACT's `targetDatePlaceholder`. The trigger shows nothing about the draft. [Prototype](https://claude.ai/code/artifact/38da2bb5-c7b3-4d00-b1f2-72ff6ed90f40).
- [The shared picker sheet's interface](https://github.com/Selftend/selftend/issues/1185) — **two layers, not one**: `PickerSheet` (chrome + the draft cycle, taking `children`) and `ThemedCalendar` (the library wrapper owning the four modes plus `locale`, `firstDayOfWeek: 1` fixed, and a locale-derived `hourCycle`). `children` rather than a mode enum, because the chrome's **third** copy wraps a *different* picker library — `time-field.tsx`'s iOS spinner — so an enum would leave one copy alive forever. The sheet renders through **`PressShieldModal`** (#1118, which landed after this map was charted and already owns the #1054 gate and the reduce-motion collapse), deleting three gate copies and three ternaries. All four field components survive; `time-field.web.tsx` is **deleted** and ☠️ **`TimeField`'s `onCommit` dies with it** — internal drafting makes it fire at the same instant as `onChange`. Footer is declarative `onClear`, and `Clear` confirms null and closes. ☠️ Found in passing: in `datetime` mode the card **halves from 300px to 150px** when the view switches, on every mood/journal/gratitude/sleep edit, and `containerHeight` cannot fix it — the spec fixes it with a card `minHeight`.
- [How the CBT and ACT Target date fields converge](https://github.com/Selftend/selftend/issues/1186) — identical component, clamp, and format; deliberately **not** the same validation mechanism, and deliberately **not** the same output. `minDate` is today for both, and the edit-path edge (both screens can meet a target date already saved in the past) is solved with a **`disabledDates` predicate** — everything before today disabled *unless* it is the stored value — so ruling 3 stays literally true instead of approximately. Format goes through a new shared `formatDayKey(dateKey, lang)`, ⚠️ fenced to the trigger plus ACT's two displays and explicitly **not** retrofitted onto the other `parseLocalNoon` callers, which want denser formats on purpose. Both guard with the existing `isValidDayKey`, but CBT in its Zod schema and ☠️ **ACT in its repository — ACT has no Zod schema and no react-hook-form at all.** ☠️ Three premises broke: **the CBT goal date is never displayed anywhere** (write-only, so there is no read-only display to reformat), **CBT milestones have a `target_date` column and a live form field with zero UI** (every one is null and always has been), and **CBT is missing the same validation the ticket blamed only on ACT**.
- [Regression risk and proof for the already-shipped pickers](https://github.com/Selftend/selftend/issues/1187) — ☠️ **the riskiest change breaks no existing test**: `date-time-field.test.tsx` has *no* commit-semantics coverage (its three tests are the two gates plus "opens the picker"), so ruling 6 can ship across all six mood/journal/gratitude/sleep call sites with the suite green. So the spec **pins today's live-commit behaviour first, then inverts it in the same PR** (two commits — ⚠️ which squash on merge), and labels the inversion so a reviewer doesn't read it as the "tests rewritten to match broken behaviour" anti-pattern. All five `TimeField` tests are affected — **two deleted** with the web fork, three rewritten, and **one added** for dismiss-discards, which nothing asserts today. ☠️ **e2e has ZERO date/time picker coverage** (40+ specs, no references; only testID is iOS-only `time-picker-spinner`) — the spec adds exactly one, extending `cbt-goal.e2e.test.ts`, which already walks past the target-date field and already covers the edit path. Locale proved by asserting **rendered output, never the prop**; mutation-verify exactly two (draft-discard, the gate). Two blind spots **accepted, not closed**: `reducedMotion` (CI never sees the animated variant) and phone width — the latter now ticketed. Two of the ticket's four bullets were already answered by #1185.

- [What replaces the web time input, at each of its five call sites](https://github.com/Selftend/selftend/issues/1191) — **nothing in the library does**: ☠️ its web time control is a bare `PanResponder` drag surface with **no `tabIndex`, no role, no `aria-*`, and not one accessibility prop anywhere in its `time-picker/` directory** — no keyboard, no click-to-select, no mouse wheel. So the replacement is ours: an inline **`HH : MM` numeric pair** (plus an AM/PM `SegmentedControl` in 12-hour locales), typed rather than dragged, reverting on blur, hosted as `PickerSheet` `children` — a **sibling component, not a `ThemedCalendar` mode**, and **web-only** (`wheel-native` is a real snapping wheel and stays). ☠️ **`TimeField` opens no sheet on web at all** — the control renders inline at all five sites, so ruling 6 does not reach web time entry and the commit boundary is blur-with-a-valid-value (which still does *not* revive `onCommit`). The same wheel already ships at **six `datetime` call sites** and is ruled **in scope**; on web `datetime` becomes calendar + time row in **one view**, which ☠️ **voids #1185's `minHeight`** because the view switcher that caused the 300→150 collapse is gone. 12/24 goes locale-derived — ⚠️ **reversing this map's out-of-scope ruling** on the two native `is24Hour` flags, whose stated reason did not survive (ruling 4 preserves the *picker*; `is24Hour` is a prop it already takes) — but ☠️ **`formatHHmm` stays 24-hour: it is a wire format**, written to `preferred_time_of_day` in Postgres, so display moves to a sibling `formatTimeOfDay(time, lang)` exactly as #1186 did for dates. `time-field.web.tsx` dies and `TimeField` becomes one file, ☠️ **because jest never resolves `.web.tsx`** (default platform `ios`), not for #1185's stated reason. Proof is one e2e on the reminders row. Spun out [#1235](https://github.com/Selftend/selftend/issues/1235) (☠️ the wheel silently keeps the old minute when dragged to `:00` — `0` is falsy); amended #1205 (the control's a11y contract) and #1231 (its phone-width proof). ☠️ The ticket's own split was wrong — **1 `compact` site, not 2** — and the modal-in-modal worry is moot (and would have been fine: RNW's `activeModalStack` hands the top modal the trap, and iOS already nests today).

- [Do the picker sheet and the inline time control work at phone width?](https://github.com/Selftend/selftend/issues/1231) — **width was never the risk**: the day grid is percentage-sized (`99.9/7 %`), so it can only shrink — measured **7 per row and 0px overflow at every width down to 300px, both locales**. ☠️ **Bulgarian is NOT the width stress case** ("септември" 80.5 vs "September" 79.3, in a 191px slot; nothing clipped anywhere), and the #1184 footer fits with ≥81px spare at 320 — the quiet `Clear` it needs is the **existing `ghost` variant**. Two real failures instead. ☠️ **Vertical**: card heights are width-invariant, and the proposed web `datetime` sheet is **521px** — it does **not** fit an iPhone SE with Safari toolbars (505 available), and ☠️ **in landscape (327 available) every variant overflows, including the picker shipping today** — with no scroll container and `justify-center`, the clipped part is the **footer**, i.e. `Done`. ☠️ **The compact 12-hour control collides with the `Switch`** below ~324px (3.5px overlap at 320, visually confirmed) because its right edge is pinned at x=250.5 while the switch moves; ⚠️ the ticket's framing was inverted — at phone widths the row is in its **stacked** branch, which is the roomy one. Three owner rulings: **(1) the supported floor is 360dp** — the collision then cannot occur, but ⚠️ **the spec must state 320 is unsupported** rather than leave it silently broken; **(2) `PickerSheet` gains a scroll container**, which fixes the SE case, landscape, *and* the already-shipped picker; **(3) the modal gutter becomes `p-3 sm:p-6`**, keeping the 340px cap — measured to lift the day target from **38.1 → 41.5 at the 360 floor**. ☠️ `max-w-[340px]` only binds at **≥388px**, so the gutter — not the cap — sizes the card on every phone; and the real tap target is **42.1 × 42.8 with 3px dead gutters** (the library insets its `<button>`), a **ceiling the 340 cap makes 44×44 unreachable at any viewport, desktop included**. Clears WCAG 2.5.8 AA; misses Apple's 44pt by ~2px, accepted. ✅ Checked rather than assumed: the calendar has **no pan/swipe gesture** (`PanResponder` exists in exactly one library file, the web time wheel), so the scroll container is safe. Amended [#1205](https://github.com/Selftend/selftend/issues/1205) (the control's `HH`/`MM` inputs render **22 × 19**, under the AA floor, and `SegmentedControl` has no `hitSlop`); spun out [#1248](https://github.com/Selftend/selftend/issues/1248) (the longest Bulgarian reminder label truncates at the newly-ruled 360dp floor). [Probe + measurements](https://github.com/Selftend/selftend/tree/worktree-wayfinder-1231-phone-width).

## Out of scope

- **Supporting viewports narrower than 360dp** (#1231). The measured floor is 360: below ~324px the compact 12-hour time control paints over the reminders row's `Switch`, and the day tap target falls to 32.4px at 320. Ruled unsupported rather than fixed — ⚠️ but the spec must **say so explicitly**, because the failure is silent otherwise.

- Building **general phone-width test infrastructure** for the repo (#1187). Jest defaults to 750px and e2e runs Desktop Chrome, so nothing in CI has ever rendered a phone branch — a real gap, but its own project. Measuring *this one sheet* at phone width stays in scope and is ticketed.
- Giving the **CBT goal target date a read surface** (#1186). It is write-only today — no goal screen renders it — so the two fields converge on input and diverge on output: ACT shows its date, CBT swallows it. Out of scope because adding a row to the goal detail screen is a CBT feature decision, not date entry. Recorded here so the gap is deliberate rather than silent.
- **Wiring the CBT milestone target dates** (#1186). The `target_date date` column and the `milestones.${index}.targetDate` form field both exist and ship; only the UI never did. Left unwired — finishing it is feature work this map did not set out to do. ☠️ The spec must say so explicitly, or whoever builds the shared component finds the field sitting next to a `Controller` that does not exist and wires it up speculatively.
- Replacing `@react-native-community/datetimepicker` on iOS/Android (ruling 4 — native keeps its OS pickers).
- Any data migration for `target_date`: the column is a real `DATE`, so no invalid value can have been stored.
- Trimming the ~45 dayjs locale bundles the picker ships unconditionally into the web build (#1183). Real weight, but reducing it means patching the package, and it is not on the way to this destination.
