### 1.1 The honest ceiling - what this spec does not promise

The map was charted against a `calm` result: six sitelinks, a knowledge panel with a logo, a description, founders, a founding date and a row of social profiles. The two research tickets established, from Google's own documentation, that none of that is reachable from the site, and **why** matters more than the verdict because two of the reasons the map started with were wrong:

- **Sitelinks cannot be requested, and never could** ([#2400](https://github.com/Selftend/selftend/issues/2400)). Every control Google ever shipped was negative - a block tool in 2007, a demotion tool in 2011, both since removed - and the current documentation reads "at the moment, sitelinks are automated". ☠️ **Google documents no threshold of any kind** - no page count, no site age, no query volume, no link metric. "Too small for sitelinks" is folklore. What Google documents is four structural signals: titles and headings, a logical structure with important pages linked from other relevant pages, concise anchor text, no repetition. Three of the four were already ruled by [indexability.md](indexability.md) § 4 and § 7; the fourth, internal linking, is § 7 here. **The site's defect was never that it held few pages; it was that it held nothing a brand searcher could want a shortcut to.** Sitelinks stay Google's decision, with no request path, no guarantee and no instrument (Search Console has no sitelinks report).
- **No on-site path to a knowledge panel exists** ([#2401](https://github.com/Selftend/selftend/issues/2401)), and the reason is **not** that panel text comes from Wikipedia - Google documents no source requirement and its own blog says Wikipedia "is not the only one". The reason, verbatim from Knowledge Panel Help: _"To maintain the integrity of search results, our current policy doesn't manually create or delete Knowledge Panels."_ Claiming a panel only edits one that already exists; Google Business Profile names "online-only businesses" ineligible; structured data is documented to influence _which_ logo shows inside a panel, never to create one; `sameAs` has no documented outcome attached. And Founders / CEO / Founded have no true values: **no registered legal entity exists** (`docs/costs.md`, checked 2026-08-20).
- **The site name** renders as the bare domain while every documented on-site input is already correct (`WebSite.name`, `og:site_name`, `<title>`); the one remaining documented input is off-site references, which this map refuses. A wait, not a task.
- **The AI Overview** is fed by ordinary indexed pages; Google documents "no special schema.org structured data that you need to add". Out of scope (§ 13).

So what this spec builds stands on its own reasons - a stranger can read what a concept is without an account; a person on any public page can reach every other; the block says two more true things - and any change to the brand result afterwards is a side effect Google may or may not grant. **No page here is judged by its search result** (§ 2).

## 2. The carve-out is the motive test, and it grants nothing

Decided on [#2399](https://github.com/Selftend/selftend/issues/2399) (owner, 2026-09-15, four rounds). The amendment text is verbatim in that ticket's resolution comment and is applied to [marketing-plan.md](marketing-plan.md) in the same change as this spec.

**The finding the map turned on.** [#2289](https://github.com/Selftend/selftend/issues/2289)'s definition of `readable` is one clause - _"the surface tells its crawler truthfully what each page already says"_. The words _"writes no new copy and creates no page"_ sit in a different sentence describing what the shipped indexability spec did. **Ruled descriptive, not binding.** So the carve-out grants nothing: a page built from content the app already holds never collided with `readable` in the first place. It is a **jurisdiction line**, stating which side of an existing line something falls on.

- **Scoped to motive** - not to the brand query (unenforceable; nobody controls which query surfaces a page) and not to the surface (it would license everything the site ever does). **No third category noun**: `readable` and `pursuit` stay the only two, and the test is named instead, matching the plan's habit (_the admission test_, _the sizing test_).
- **The motive test.** _Remove every search engine from the world. Does this - this page, this page set, this string, this property - still exist, and still read the same way? If not, the difference is pursuit._ For a set: **if removing the search consideration changes which pages are in the set, the set is written to rank.**
- **On the readable side, none of it new permission:** a public page from content the app already holds (precedent: [indexability.md](indexability.md) Appendix A.1); the framing strings a page cannot exist without (a heading, a title, a one-line lede) where the source screen has none that stands alone; a title written for legibility rather than lifted from the H1 where a constraint makes the H1 unreadable in place (precedent: the landing's short form, [#2007](https://github.com/Selftend/selftend/issues/2007)); a structured-data property the page does not visibly display - structured data may **describe, never claim**. [#2291](https://github.com/Selftend/selftend/issues/2291)'s refusals are untouched: they failed on truthfulness, not visibility.
- **Two new refusals beside the standing ones:** **no page set sliced to look structured** (splitting content the site already holds across more URLs to present a fuller shape is a page written to rank in disguise, and without this clause the membership rule is evaded by slicing rather than adding); and **no judging a published page by its search result** - Search Console stays a standing-surface reading, never an arrival, and never a verdict on a page. ☠️ The second is an _after_-rule the counterfactual structurally cannot catch: the test settles admission once, about an artifact that does not exist yet, and drift afterwards leaves no mark on the artifact. Both are written down because a rule that only guards the door fails silently.
- **Where it lands:** `#### The motive test` under square 3, after _The admission test_; one clause and a tense change on the readable/pursuit paragraph (_wrote_ no new copy, _created_ no page - a description, never a rule); one clause in the § 6 web-ASO row's reason cell, **verdict untouched**. Nothing else in the plan moves: not the standing-surface classification, not the 2026-12-10 sitting, not the worked-channel deferral, not the no-spend rule - all four govern whether the surface is _worked_; this governs what it may _say and hold_.
- **Two residues [#2399](https://github.com/Selftend/selftend/issues/2399) handed to assembly, both applied in this change:** [indexability.md](indexability.md)'s "The word" line carried the same ambiguity in the document a contributor actually opens when adding a route - _"no new copy, no new page"_ is dropped and _"no choice made for a query"_ kept; and the sitting's coverage line was pinned to _"eight of eight"_, a count this spec changes - it now reads _"all of the index list"_.

## 3. The page set - explainers, chosen by a principle

Decided on [#2403](https://github.com/Selftend/selftend/issues/2403) (owner, 2026-09-15, six rulings). The principle is the durable half; the list is only what it produces today.

### 3.1 The principle

> **A page on `selftend.org` may carry content the app already holds when that content exists to explain a concept to someone who does not know it yet. Content a person operates - a form, a record, a log, a session - stays behind the gate.** The test is what the content is _for_, not which screen it currently sits on.

The app's content splits cleanly: **instruments** (thought records, check-ins, journal entries, habit logs, mood and sleep entries) fail the motive test - a stranger cannot use one without an account, so a public copy has no reason to exist except to be found; **explainers** pass it directly - they would still exist with every search engine removed. It also closes a real gate: **today a person must create an account to read an explanation of what cognitive distortions are.**

- **The boundary is content, not route.** Applying the principle route-first (only screens with a `learn` surface) would silently drop ACT, whose six principles and four pillars are explanations rendered as cards on its module home. Ruled by content, so ACT is in.
- **The audience is a public good** - anyone who wants to understand the idea. The page teaches and stands on its own; routes into the app are present but **quiet** - the header's brand mark, never a call to action (§ 7.3 settles which).
- **The content lives in both places.** The public page is a second home; the in-app screen is untouched. ⚠️ This is a **deliberate departure** from the carve-out's Appendix A.1 precedent (_"the strings existed, only their home moves"_), which was a move. Duplication is still inside the motive test - the page exists to explain, not to rank - and the two must share one source so they cannot drift (§ 4).
- **Framing is the lede only; titles stay as the app has them.** The carve-out's permission for framing strings and a legibility-driven title is the door keyword-chosen copy would walk through. Worked example, refused: retitling CBT's _"Thinking patterns"_ to _"Cognitive distortions: common thinking patterns"_ passes a naive legibility argument and is exactly a keyword-chosen string. A page may add a lede, and section headings only where the app has none; **the title is whatever the app already calls it, unchanged.** Some titles will read opaquely to a stranger; that is the accepted price of a rule that is enforceable rather than a judgement that erodes.
- **Crisis guidance on every public page, in a fixed footer.** A public DBT explainer opens _"for when feelings run high and fast"_ and can reach a distressed stranger who never saw the landing. One identical, quiet route to `/crisis`, in the same place every time, clearly separate from the content by construction (`AGENTS.md`). It appears on pages whose subject is not distress; that is intended - the per-page alternative needs a judgement, and the safest-looking page is exactly where it would get dropped. [#2411](https://github.com/Selftend/selftend/issues/2411) settled its footprint: **all public pages, the existing eight included**, because it rides on the one footer (§ 7).
- **Refused, with the reason:** the **nine-page-per-tool set** - nine pages each named for a thing a person could want is the shape of Calm's sitelinks, and creating pages to obtain the feature is a page written to rank ([#2399](https://github.com/Selftend/selftend/issues/2399)'s slicing refusal). ☠️ **"More pages would help" is not an available argument** and the spec never makes it: the baseline measured 1 of 8 indexed with seven queued and uncrawled, so nothing about the page count is known to be limiting. The set stands on what a page is _for_.

### 3.2 The five pages, and the reason each exists

Every source below already exists in `en` **and** `bg`. Titles are existing app strings. The "why it exists" column is the convention § 0 names, and it is the same sentence for all five because the principle is one sentence.

| Page       | Route         | Title (existing app string)                             | Content it carries                                                                                                                                    | Why it exists                                                          |
| ---------- | ------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| CBT        | `/cbt`        | Thinking patterns (`cbt:learn.title`)                   | `cbt:learn` (description, _Use gently_, pacing) + `cbt:distortions` - **17** patterns, each with a title, a short description and a reflection prompt | so a person can read what the thinking patterns are without an account |
| DBT        | `/dbt`        | What DBT is (`dbt:learn.title`)                         | `dbt:learn` - what it is, why "dialectical", where to start, pacing, and the four skill groups                                                        | so a person can read what DBT is without an account                    |
| ACT        | `/act`        | Acceptance & Commitment Therapy (`act:home.fullTitle`)  | `act:principles` (six) + the pillars + `act:home.description`. **The one assembled page** - it has no single learn screen behind it                   | so a person can read what ACT is without an account                    |
| Meditation | `/meditation` | Meditation (`meditation:module.home.title`)             | the three pieces of context - attention and peripheral awareness, the gardener's mindset, the path is not linear                                      | so a person can read the meditation framework without an account       |
| Habits     | `/habits`     | Habit building - core ideas (`habits:learn.indexTitle`) | `habits:learn.cards` - ten cards, each with a title, a short line and a body                                                                          | so a person can read the habit framework without an account            |

Two rules this table applies, both assembly's to pick and both constrained to existing app strings ([#2403](https://github.com/Selftend/selftend/issues/2403) ruling 5, [#2404](https://github.com/Selftend/selftend/issues/2404) answer 1):

- **The route is the app's own slug for the module or tool the content belongs to** - the last segment its gated routes already use (`modules/cbt`, `modules/dbt`, `modules/act`, `tools/meditation`, `tools/habits`). An existing identifier, not chosen copy; short; and it survives a second explainer for the same module without a rename, because the page is the module's public face, not one screen's. Rejected: naming the route for the content (`/thinking-patterns`) - a slug written for the page is the one string on it that is not an app string, and it is the string most easily written for a query.
- **The title is the title of the screen the content already has.** Where the content has a learn screen, its title (CBT, DBT, habits); where the page is assembled from a module home, the module's full title (ACT). The rule is consistent even though the shapes differ - CBT's is an explainer title, ACT's a module title - and that is accepted rather than smoothed, because the alternative is a title written for the page. **One exception, and it is the carve-out's own permission rather than a judgement: where a learn screen's title is an instruction rather than a name, the page takes the module's name** - still an existing app string, so no new copy. Today that is meditation alone: `meditation:module.learn.title` is "Learn the framework", which inside the module refers to something the reader has already met and on a public page names no subject at all - and under § 7.3 it would be the footer label on every public page, the one entry that names no topic. So `/meditation` takes `meditation:module.home.title`, "Meditation" (Appendix A.18). ⚠️ This is not the retitling § 3.1 refused: that added keyword text to an already legible title; this replaces an instruction that is unreadable out of context - legibility, never keyword fit ([#2399](https://github.com/Selftend/selftend/issues/2399)'s third permission, precedented by the landing's short form).

☠️ **Three of the five carry gated module content, and this is the one place the map's premise moved after the set was decided** - see § 3.3.

### 3.3 The module gate reaches three of the five

[#2403](https://github.com/Selftend/selftend/issues/2403) was resolved at 16:08 UTC on 2026-09-15. At 16:06 UTC, on the twin map [#2445](https://github.com/Selftend/selftend/issues/2445), the owner **gated all three modules - CBT, ACT and DBT** ([#2446](https://github.com/Selftend/selftend/issues/2446)): a gated module is live in the code and kept off the production surfaces until it clears a stated readiness bar (one user-test sitting per module), and **module work is frozen while gated except the return path**. The mechanism ([#2448](https://github.com/Selftend/selftend/issues/2448), resolved 18:52 UTC) is a committed **live list**, empty today, plus a build-time switch for the testing places; every surface asks one predicate, **the public landing page's CBT and ACT cards included** - they are absent on production while no module is live. The map's own comment of 12:32 UTC had said it: if the modules leave the production surfaces, module content stops being _existing content_ for any public page this map builds.

**Ruled (§ 12 items 5 and 7; Appendix A.11):**

- **The principle and the set stand.** An explainer's reason to exist does not depend on whether its module is enterable, and nothing in the gate changes what the content is _for_. All five pages are decided.
- **A module's explainer page lands with its module's return, in the same PR that adds the module to the live list** - never before. Three facts force this rather than a gated route: a public route file exists iff it is indexable ([indexability.md](indexability.md) § 3 - no third state such as "listed but hidden"), so an explainer on the index list answering the not-found screen on production would make the sitemap lie; the freeze rule makes the page module work; and a public page describing a module a person cannot enter is the one shape here that fails the motive test as a _set_ - its only reason to exist ahead of the module would be to be found.
- **Meditation and habits are tools, not modules; the gate does not reach them.** Their two pages ship first, and with them everything the five share (§ 4, § 7).
- **The landing's module cards link to their explainers when they are rendered** ([#2411](https://github.com/Selftend/selftend/issues/2411) ruling 9). While no module is live the cards are absent and the rule has no object; it binds the card and the page together on the day either returns.

## 4. The mechanism - one body, two renderers, one row

Decided on [#2404](https://github.com/Selftend/selftend/issues/2404) (a prototype of the CBT page on `prototype/public-content-page`, never merged; findings and two screenshots in `docs/research/2026-09-15-public-content-page-prototype.md` on that branch). **The machinery built for v0.19.0 carries a content page unchanged**: `applyIndexList`, the sitemap writer, `SiteHead`, `RouteHead` and `app/+html.tsx` were touched by nothing.

- **Route:** a flat `app/<slug>.tsx` outside `(app)`, where the seven policy routes sit. ☠️ **A public route must be flat**: `test/index-list.test.ts` asserts every route file outside the two groups has depth two - _"a directory route would need a file-name rule the list does not have"_ - so `app/learn/cbt.tsx` fails the existing suite. Flat routes obey the rule; nothing is relaxed.
- **Reuse or own component: neither, and both.** One chrome-free body in the module's feature folder (the prototype: `src/features/cbt/thinking-patterns-body.tsx`, the cards moved verbatim), rendered by the existing gated screen with its chrome untouched (its test passed unchanged - a pure move) and by the public route through `PolicyPageLayout` with `title` = the app's existing title and `description` = the existing subline or the lede. The two-audiences trap needed **no prop at all**: the audiences differ in chrome, and the body has none. If the body ever has to differ, the difference is a required prop, never a default.
- **Renders at export, hydrates clean.** `cbt.html` exported at 50 KB (`faq.html` 54 KB) holding the H1, subline, both framework cards, all seventeen patterns and the footer, zero loading-state occurrences - the page reads no session, so nothing on it can be a spinner. Console clean but for the three `[env]` notices of a build with no env file; no hydration error.
- **Head:** complete and identical in shape to `faq.html` - title through the template key, description from the subline, `og:title` / `og:description`, `og:url` and canonical at `https://selftend.org/<slug>` - all from `RouteHead` inside the layout, no route code. **No structured-data block** (§ 6).
- **Cost:** 303 → 304 HTML files before the prune (a flat route writes one file, no group-stripped twin); 10 kept. **One `INDEX_LIST` row is the whole machinery cost** - and ☠️ the row drags **three test pins, not one**: `test/index-list.test.ts`'s literal list, and `scripts/lib/index-list.test.js`'s export fixture _and_ its expected sitemap. The focused run missed the second file; the pre-commit hook caught it, seven tests red. Plus two rows in [indexability.md](indexability.md) (§ 3, § 4.1) and one entry in `policy-heading-outline.test.tsx`.

## 6. Structured data - two properties in, everything else refused with a reason

Decided on [#2405](https://github.com/Selftend/selftend/issues/2405) (owner, 2026-09-15, five rulings), after [indexability.md](indexability.md) § 5 was read in full.

**The frame: § 5's banked win does not exist, so truth is the only currency.** § 5 said _"no rich result is expected; the win is the logo and site-name association"_. [#2401](https://github.com/Selftend/selftend/issues/2401) removed both halves: the logo effect only picks _which_ logo inside a knowledge panel that cannot be created on-site, and the site name still renders as the bare domain while every documented input is already correct. **Not** a reason to remove the block - truthful, free, 0 errors, Bing reads JSON-LD - but the reason **no property may ever be justified here by expected effect.** The only admissible test: is it true, and does the page say it.

- **Added to `WebSite`** (a `CreativeWork` subtype; neither is valid on `Organization`):
  - `isAccessibleForFree: true` - the landing visibly renders _"Free · Open source · Private"_ and _"No ads, no subscriptions"_, and free-to-users is a standing guardrail. ⚠️ Honest scope note: on `WebSite` it asserts the _site's content_ is free to access, narrower than what the landing says about the product; the stronger claim would need `SoftwareApplication`, which stays refused.
  - `inLanguage` - restates the rendered `<html lang>`. ☠️ **Derived from `i18n.language`, never hardcoded `"en"`**: § 4.4 already rules the block is "English in the file, the visitor's language after hydration", so a hardcoded value is **false in the DOM** for a Bulgarian-preference visitor, on a block whose whole justification is that it cannot disagree with the page. Passed in by the caller the way `url` and `description` are; the module stays pure.
- **Refused, each with its reason so nobody re-derives it:** `knowsAbout` - a list of therapy names no page displays, the property most transparently chosen for what a machine might match: keyword-chosen copy in structured-data clothing, the clearest motive-test failure in the set. `foundingDate` - no page displays a date; the only defensible value is the first commit, 2026-04-15, a fact about a repository, and it would sit three lines from a `nonprofitStatus` refused for having no legal entity. `alternateName` - [#2401](https://github.com/Selftend/selftend/issues/2401) proved every on-site site-name input is already correct; there is no true alternative name; it would change nothing. `slogan`, `publishingPrinciples`, `license` - none displayed. `BreadcrumbList` - refused on **truthfulness**: the flat-route rule leaves no hierarchy to describe beyond "Home > CBT", and [#2400](https://github.com/Selftend/selftend/issues/2400) found breadcrumbs are never connected to sitelinks; a crumb here would describe structure invented for a machine.
- **The five pages stay bare.** The landing keeps the only block; `test/structured-data-surface.test.ts` (the source-grepping gate hardcoding the two files allowed to name the type) is **unedited**.
- **Neither effect-based refusal is re-opened; both justifications are upgraded.** `FAQPage` and `SoftwareApplication` stay refused - but _"the rich result went away"_ implied the refusal expires if Google reinstates the feature. It does not. They are refused because **no documented reader acts on them and Selftend gains nothing truthful by asserting them**. `SoftwareApplication` also drags in `applicationCategory`, a category noun positioning refuses.
- **The pinning rule holds and widens:** any block on any page may only restate strings its own page renders - one rule, because a test can pin a string and cannot pin a judgement. ⭐ It is what excluded two properties the owner had first selected (`knowsAbout`, `foundingDate`); recorded so the spec shows the rule doing work.
- **Corrected in [indexability.md](indexability.md) § 5 in this change** (true today, no build needed): the stated win; the two restated justifications; the three named refusals on the "Never" list; the widened pinning sentence; and the sitelinks search-box date - the feature was removed from 2024-11-21 (announced 2024-10-21); 2024-11-29 is the date Google removed its documentation. The `SearchAction` decision is unaffected. The two properties landed there on [#2468](https://github.com/Selftend/selftend/issues/2468) (§ 12 item 2): `language` is a third input to `landingStructuredData`, beside `url` and `description`, and `LandingHead` passes `i18n.language` from the same `useTranslation` call that reads the title and description.

## 7. Internal linking - one footer, every page, labelled with each page's H1

Decided on [#2411](https://github.com/Selftend/selftend/issues/2411) (owner, 2026-09-15, twelve rulings), after the link graph was measured from what production serves - not from source, because several navigation affordances render no anchor at all (§ 1).

### 7.1 The framing, and the refused framing named

**This section acts under navigability for a person.** The motive test, applied: remove every search engine - does a person on `/privacy` still want a way to `/security`, and a person landing cold on any policy page still want the rest of the site? Yes, and today six of the seven non-landing pages give that person exactly one way out. Every public page is a page someone reaches with no session - from a store listing, a Reddit thread, a shared link; the FAQ's only known referrer is a GitHub issue. The linking is owed to that reader. **The refused framing:** _link the pages so Google sees a logical structure_ - structure chosen for the feature, and it fails the motive test outright. The test recorded beside the decision: **no link in the set exists that a signed-out reader on that page would not want.**

### 7.2 The shape

- **One shared `SiteFooter` on every public page, listing every public page** - rendered by `PolicyPageLayout` for every non-landing public route and by the landing **in place of** `LandingFooter`, so there is one footer and it lists the same pages everywhere (two footers is how they drift). Every page is one click from every other and from `/` by construction. Refused: _hub only_ (today's shape with the orphans patched; a cold-landed reader still has to visit the hub) and _hub plus siblings_ (needs a per-page judgement of "family", the shape § 3 refused for the crisis footer).
- **It carries, in order:** the safety description, the crisis row, the nav list, the social links (Discord, Reddit, YouTube - the same fact on every page, kept everywhere rather than landing-only).
- **The nav list is two rows with no headings** - explainers first (what a cold reader came for), policies second (what a site must carry). The order carries the grouping; the only candidate heading strings were written for another surface, and a heading is new copy the list does not need. **The index list is reordered once, when the first explainer ships, into the same order** _(as built: the list took the footer's order on [#2467](https://github.com/Selftend/selftend/issues/2467) already - `/crisis` second, because the crisis row precedes the nav list and § 7.6's pin compares ordered arrays - so the first explainer inserts rather than reorders)_, so the sitemap and the footer read the same sequence and the pin compares ordered arrays.
- **`/crisis` appears once** - the crisis row _is_ the site's link to it; the nav list omits it. **`/` is not listed** - the header's brand mark links it on every page. And the explainer pages' quiet route into the app **is that brand mark**: the prototype's borrowed "Open Selftend" string is dropped, because a second entry beside the brand mark is a call to action wearing a footer, which § 3 refused.
- **On web the footer renders as a `<footer>` containing a `<nav>`** (react-native-web `role`) - accessibility, and what the element is. Nothing else on any page changes its element.

### 7.3 The anchor-text rule

**A link to a public page is labelled with that page's H1 - the same string its `<title>` and `<h1>` already carry** ([indexability.md](indexability.md) § 4's title = H1 invariant). "Concise" and "descriptive" fall out of the invariant for free; no new copy is written; a new page arrives with its anchor text already decided and already in both locales. Consequence: the landing's "FAQ" becomes "Common questions". Two exemptions, on purpose: the **brand mark** ("Selftend" → `/`, the site's name, not a page title) and the **crisis row** (keeps its imperative "Open crisis guidance", `common:safety.openCrisis` - an affordance, not a table of contents).

### 7.4 Buttons to routes become anchors

☠️ **A button is not an edge in the link graph, however it behaves for a mouse.** `/privacy` → `/security` and back exist today as `Pressable`s with `onPress` and no `href`; so do the gated Legal screen's five buttons and `CrisisSupportBar`. The two in-body buttons and the crisis row become real anchors (`LinkButton`, a real `<a>`, as `LandingFooter` already uses), and the rule reaches any future button on a public page whose target is a route: middle-click, "copy link", a screen reader and a crawler all agree it is a link. The Escape-origin recording the two in-body buttons carry today is a **build detail, not a decision** - kept on the anchor, or its drop documented.

✅ **The rule reaches SHARED CHROME too, decided on [#2496](https://github.com/Selftend/selftend/issues/2496) (2026-09-17).** Two buttons were left alone when this section first landed, on the reading that it governed a page's own body: `CrisisSupportCallout`'s _Open crisis support_ (on `/faq`, and on four gated screens beside it) and the cookie banner's _Cookie policy_ (root-level chrome on every web page). Both are now `LinkButton`s. The sentence above already said _any_ button on a public page whose target is a route, and its four reasons - middle-click, copy link, a screen reader's link role, a crawler - do not depend on whether the button sits in the body or in the chrome. ⚠️ **Crawlability was never the argument here**: the footer already links `/crisis` and `/cookies` from every public page, so what the conversion buys is the semantics a _person_ gets. For the crisis callout that is the strongest case on the page - copying the link to hand to somebody else is a real thing to want.

☠️ **The rule stops at the web boundary, and that is not a loophole - it is the whole basis of it.** `app/index.tsx` renders `LandingScreen` on web and `AuthLandingScreen` on native, so `AuthLandingBlock`'s four route buttons (`/crisis`, `/terms`, `/privacy`, `/cookies`) **never render on web at all**. There is no `<a>`, no middle-click, no copy-link and no crawler on a native screen, so converting them would buy nothing and cost the push helper. Written down because a grep for `pushWithOrigin` on a route finds them immediately and they read exactly like the two this issue converted. The same holds for the gated Legal screen's five buttons and Settings' `/cookies` button: **gated screens are not public pages.**

### 7.5 The landing's module cards

Each landing card (CBT, ACT) links to its module's explainer - on the motive test: a person reading the card and wanting to know what CBT actually is has nowhere to go but sign-up. **No card is added** for DBT, meditation or habits so that every explainer gets a body link; that would be structure chosen for the feature. ⚠️ Under the module gate (§ 3.3) the cards are absent while no module is live, so this rule binds a card and its page together on the day a module returns, and is built in that return.

### 7.6 The pin - the fourth on the index list

A **render-level test**: render the footer and assert its `href`s equal `INDEX_LIST` minus `/`, **in list order**, importing the list from `scripts/lib/index-list.js`. A route added to the list fails the footer test until the footer knows it, so **a future route cannot land orphaned**. The per-route anchor text lives in a small route → i18n-key map beside the footer, and the same test asserts the map's keys equal the list. The landing's two card links get their own assertion in `modules-section.test.tsx`. A source grep was refused: it matches a string, not an edge.

### 7.7 The facts carried, not decided

The landing's `/sign-up` and `/sign-in` links are off the index list and answer a real 404 to a crawler by design ([indexability.md](indexability.md) § 6.4) - a person is unaffected (the not-found file hydrates into the real screen), the status code is the only untrue thing, and it is very likely why `site:` still returns the dead `/sign-up`. Unchanged, and outside this map.

- **A Wikidata item, a Wikipedia article, any new social profile** - owner ruling 2: on-site only. A new social profile is a new standing surface, so the plan's admission test governs it; and none is a documented route to a knowledge panel.
- **Link building and outreach · keyword-chosen copy · any page written to rank** - [marketing-plan.md](marketing-plan.md) § 6, refused on principle. ⚠️ Creating pages _in order to obtain sitelinks_ is precisely a page written to rank; the set in § 3 stands on a reason that is not the feature.
- **Store keyword work · Core Web Vitals as a ranking input** - already out of scope on [#2281](https://github.com/Selftend/selftend/issues/2281).
- **A Calm-equivalent knowledge panel** - no creation path, and no registered entity for its rows to be true of.
