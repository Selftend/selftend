# Outside-in baseline: what a crawler sees of selftend.org, 2026-09-29

**Ticket:** [#2843](https://github.com/Selftend/selftend/issues/2843), wayfinder map [#2842](https://github.com/Selftend/selftend/issues/2842). **Branch:** `research/findability-baseline`, never merged — the branch name is the citation, like `research/indexability-baseline` before it.

**Method:** every reading is a plain `curl` of a public URL from outside, 2026-09-29 (edge PoP SOF), no auth, no form, no rendering. The spec verified against is [docs/indexability.md](../indexability.md) §§ 2–6 (as built, v0.19.0, extended through [#2470](https://github.com/Selftend/selftend/issues/2470)), with [docs/deployment.md](../deployment.md) § _Cloudflare zone settings_ as the dated record of the zone toggles. Readings are standing-surface reads — what the origin serves — never verdicts on a page.

**The answer in one line:** every as-built guarantee holds on the live origin; the only defects found are three stale sentences in two docs, all the same fact — the Cloudflare managed AI-crawler block that [#2702](https://github.com/Selftend/selftend/issues/2702) turned off on 2026-09-23 is still described as on in [indexability.md](../indexability.md) § 6.5 and in two places in [deployment.md](../deployment.md) outside its zone table.

## DEFECT LIST (by severity — none is a live-origin defect; all three are stale doc text describing one retired toggle)

- **D1 — [docs/indexability.md](../indexability.md) § 6.5 asserts the opposite of the decided state.** "Cloudflare's managed AI-crawler block stays on. It is prepended, never replaced" — the toggle (now "Bot Preference Sync") was turned **off by decision** on 2026-09-23 ([#2702](https://github.com/Selftend/selftend/issues/2702)), and [deployment.md](../deployment.md)'s zone table records it with the date and the verifying `curl`. By the spec's own § 0 rule — where the file and a resolution comment disagree, the comment wins and this file has a defect — § 6.5 is defective, and § 1's "After this spec" column ("the managed block prepended to `public/robots.txt`") carries the same stale claim. Anyone re-verifying the site from indexability.md alone would file the _correct_ 67-byte robots.txt as a regression — this baseline nearly did.
- **D2 — [docs/deployment.md](../deployment.md) § _Web Build_ contradicts its own zone table.** The export paragraph still ends "…Cloudflare prepends its managed AI-crawler block to it at the edge, which is expected." Same file, § _Cloudflare zone settings_, Bot Preference Sync row: off since 2026-09-23, response is byte-for-byte `public/robots.txt`. One of the two sentences is wrong; the dated, curl-verified one is right.
- **D3 — [docs/deployment.md](../deployment.md) § _Public Routes To Verify_ describes the retired response.** "`/robots.txt` is Cloudflare's managed block followed by the repo's own file" — a post-deploy checker following this section verbatim would fail a correct deploy.

Nothing else. The live origin passes every as-built check in §§ 2–6: ten routes with self-owned heads, title = H1, `lang="en"`, one footer/one nav linking the whole list in order; a clean XML sitemap equal to the index list; real 404s with a `noindex` not-found file for auth, gated and garbage paths; one origin with path-and-query-preserving 301s; JSON-LD on `/` alone and truthful; staging `noindex` with no sitemap.

**Observation, not a defect:** `/index.html` still answers `307 → /`, unchanged since the 2026-09-09 baseline. The spec is silent on it, nothing links it, and the sitemap never lists it; recorded so the next baseline knows it is standing behaviour, not drift.
