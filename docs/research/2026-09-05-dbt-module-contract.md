## 3. The cleanest template migration

**`supabase/migrations/20260715_routines.sql:24-135`** — the **only** migration in the repo that creates an encrypted table from birth. Every `*_encrypt.sql` (20260587–20260663, all 38 of them, incl. every `act_*`) is a retrofit (`add column *_enc` → backfill → `rename to *_data` → view), so copying one of those drags in the migration dance. `20260715` has the base table, cap, index, `updated_at` trigger, RLS, view, guard, three `INSTEAD OF` triggers, grant — and a child table with parent-ownership RLS (`routine_steps:139-182`) for the plan/own-items shape decision 14 asks for.

Pieces a copy must change (for `dbt_coping_plans`):

1. `public.routines_data` → `public.dbt_coping_plans_data`; `name_enc` → one `*_enc bytea` per free-text field; drop the reminder columns (DBT reminders live on `user_preferences`); add the module's plaintext structured columns (enum picks with `check`) and, if dated, `<ts>_offset_minutes smallint check (between -840 and 840)` nullable, no default.
2. `constraint routines_data_name_enc_size` → one per `_enc` column, inline.
3. `routines_data_user_created_idx`, `set_routines_updated_at` → renamed.
4. `routines_manage_own` → `dbt_coping_plans_manage_own`; keep `for all to authenticated using ((select auth.uid()) = user_id) with check (…)`.
5. View `public.routines` → `public.dbt_coping_plans`, one `app.decrypt_text(<col>_enc) as <col>` per field, every plaintext column passed through.
6. `routines_guard(p_name)` → a guard per free-text field with the cap the spec sets (`char_length`, not bytes); slice-then-sanitize is client-side.
