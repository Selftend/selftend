# DBT overlap inventory: every workbook skill against the shipped surface it would link to

Ticket #1981, part of map #1980. Read-only research against `dev` at `474a648d` (2026-09-05). Source rows are the book study's §2 (`dbt-workbook-study.md`, 127 rows I.1 … 12.2); the book is paraphrased throughout and no worksheet text is reproduced. Code is cited as `path:line`. The class column is **provisional** — the decision tickets rule — but each is argued against the shipped shape, not the shipped name, and against the map's settled decisions (D1–D16 in #1980 § Settled while charting).

Class vocabulary: **link** (send the person to a shipped surface as-is; maybe an "Also try" row), **build** (DBT-native surface because the book's shape differs materially — D4), **omit** (not in the spec at all — D5/D7/D13), **learn-only** (paraphrased on a DBT learn page; no tool, no record — D10/D12).

## 1. Premise checks

### P1 — "meditation practices are info-only" → ✅ holds, with two sharp edges

- `src/features/meditation/meditation-practices-section.tsx:17-22`: the section is an "info-only reference … it launches nothing … neither writes a session row". Each card expands to `t("practices.<slug>.instructions", { returnObjects: true })` (`:39-40`) — four instruction strings per practice, no timer, no save. `src/features/meditation/practices.ts:11-15` calls it "a reference list, not a launcher". The route `app/(app)/tools/meditation/practices.tsx:1-3` is a bare re-export; `?practice=` only pre-opens a card (`meditation-practices-screen.tsx:21-23`).
- Six practices: `breath-awareness`, `body-scan`, `loving-kindness`, `observing-thoughts`, `mindful-walking`, `mindful-eating` (`practices.ts:16-23`). Three of them are the map's named link targets (body scan, loving-kindness, observing thoughts).
- Edge 1: the thing that DOES write a row — the sit timer at `/tools/meditation/session` — tags a sit with `techniqueUsed: TmiTechnique`, a closed TMI enum (`breathAtNose | followingTheBreath | connecting | bodyScan | wholeBodyWithBreath | metacognitiveAwareness | effortlessness`, `src/features/meditation/types.ts:9-16`), plus `stageAtSession`, dullness/distraction levels and TMI obstacle tags (`:41-63`). There is no value for loving-kindness, wise mind or observing thoughts. A DBT sit recorded there would be a mis-tagged TMI stage sit.
- Edge 2: a routine `meditation` step and the CBT programme's `calmingDaily` leg count ANY `meditation_sessions` row on the captured day (`src/features/routines/derive.ts:190-192`, `src/features/cbt/program-definition.ts:216-226`). So "link to a practice" gives a person reading instructions and, if they then run the plain timer, a dated record — but the record cannot say which practice it was.

### P2 — "the CBT exposure ladder is a twin of the assertive-situation hierarchy" → ☠️ half-wrong: the ITEM is a twin, the SESSION and the copy are not

Shipped shape (`src/features/exposure/types.ts:1-33`, `schemas.ts:7-16`):

- `exposure_hierarchies { title, anxietyType }` → `exposure_items { description, sudsRating 0–100, completedAt }` → `exposure_sessions { preSuds, postSuds, durationMinutes, safetyBehaviorsUsed, safetyBehaviorDescription, notes, completedAt }`.
- Ranking is implicit: items are listed by `suds_rating` ascending (`repository.ts:130-143`); there is no `position`/rank column. Items are entered only in the create wizard's field array (`app/(app)/modules/cbt/exposure/new.tsx:50-56, 152-199`); the detail screen has no add-item affordance (grep of `[id].tsx` for `saveItems|append|addItem` is empty), only per-item "Start"/"Repeat" (`[id].tsx:263-264`).
- Running a rung = a session sheet of SUDS before/after + minutes + safety behaviours; saving it stamps `exposure_items.completed_at` (`repository.ts:240-258`). No sequential gate — any item can be started first.
- Routine/programme: `exposure` is steppable (any session `completedAt` on the viewer-local day, `derive.ts:200`), and the CBT programme's `EXPOSURE_LADDER` milestone counts hierarchies created since the programme started (`program-definition.ts:180-188`). No captured offset (`supabase/migrations/20260907000000_record_days.sql:18-21` lists `exposure_sessions` among the tables that name no day).

Book shape (study 10.8, A.47): ten situations ranked by difficulty; each rung = write the 4-line assertiveness script, rehearse, choose time and place, commit to a date, do it, evaluate, climb.

Match: description + 0–100 difficulty + done-mark is exactly the rung. Mismatch: (a) the rung carries a SCRIPT (10.4's four lines) and a DATE commitment; the item carries neither; (b) the session record is anxiety-exposure semantics (SUDS drop, safety behaviours) not "did I ask / how did it go"; (c) all copy is `exposure.*` in the `cbt` namespace and the hierarchy is labelled by `anxietyType`; (d) a DBT hierarchy saved there would light the CBT programme's exposure milestone and Home's "last exposure" row (`repository.ts:212-220`). Verdict: reusable **item shape**, not a reusable surface. A DBT assertiveness hierarchy is a `build` that borrows the `{description, rating, completedAt}` item + `NumberRating` pattern and adds a script slot; see §4.

## 4. Facts a later ticket needs

**Mood tracker emotion list.** Fixed seed of 22 ids with emoji and valence (`src/constants/emotions.ts:9-32`), seeded as real rows per user once (`emotion-preferences-repository.ts:98-112`, `user_preferences.emotions_seeded`), then user-editable: rename/re-emoji builtins, add custom `{name, emoji, is_custom}` rows, reorder by `position`, soft-remove via `removed` (`:114-153`, `:155-161`). `mood_logs.emotions` is a `text[]` of ids. Custom ids are DROPPED when a check-in hands emotions to a thought record because the thought-record step renders builtins only (`thought-record-handoff.ts:14-17`). A DBT emotion record reading the same list faces the same choice: render `useEmotionDisplay().allEmotions` (customs included) or `EMOTION_GROUPS` (builtins only). No "primary vs secondary" or body-sensation vocabulary is attached to an emotion; body sensations are free-text chips (`mood/body-sensations.ts:1-12`).

**Grounding's session flow and what a timed script needs.** A technique is `{slug, icon, hue, kind: senses|guided, steps[{icon, hue}]}` in `src/constants/grounding.ts:9-19` plus three index-aligned i18n arrays `steps`, `stepLabels`, `stepHints` under `cbt:grounding.techniques.<slug>` (`grounding-flow.tsx:102-113`). The live screen is Next/Back/segment-jump on `FocusSessionShell` (`{eyebrow, trailing, children}`, `focus-session-shell.tsx:38-46`) with no per-step clock (`grounding-session.tsx:151-152`); the flow measures wall-clock minutes from mount and saves `{exerciseName: slug, durationMinutes, stepsCompleted, stepsTotal}` into `mindfulness_sessions` (`grounding-flow.tsx:54-65`); finish-early saves the furthest step reached. A DBT timed step script needs: (1) a per-step `durationSeconds` in the technique config, (2) a countdown per step (breathing's `session.tsx` and the meditation sit's wall-clock anchor already have background-safe timing), (3) an auto-advance vs "next when ready" choice, (4) a home for the row — see the next fact.

**☠️ The shared-table split rule.** `mindfulness_sessions` is shared by breathing and grounding, told apart ONLY by `exercise_name ∈ groundingSlugs` (`derive.ts:151-155`); every other name is a breathing session — in routines (`derive.ts:176-186`), the starter offer (`starter-offer.ts:118-120`) and breathing history (`mindfulness/repository.ts:127` selects `not in (grounding slugs)`). A DBT PMR or safe-place session saved there under a new slug would be tallied and listed as BREATHING. Either register DBT session slugs in `groundingSlugs` (then they count as grounding steps and show in grounding history) or give DBT sessions their own table (D14 suggests per-tool tables anyway).

**Meditation cannot tag a DBT sit.** `meditation_sessions.technique_used` is the TMI enum (`meditation/types.ts:9-16`) and every sit carries `stage_at_session`; there is no free technique.
