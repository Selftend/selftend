# What a twelfth, tool-less reminder target costs: the fan-out

Research for [#2415](https://github.com/Selftend/selftend/issues/2415) (map [#2409](https://github.com/Selftend/selftend/issues/2409)). Read-only, verified against `origin/dev@3d9be785` on 2026-09-15. Every row states a fact and a verdict — **generalises** (the eleven-target pattern takes a tool-less key with only a prefix edit) or **assumes a tool** (with the exact assumption). No recommendations; the grilling tickets decide.

## Premise corrections

- The repo carries **three different counts** of the same surface: `docs/app-store-review-information.md:72,177` says "Ten reminder targets"; `src/components/app/module-home-header.tsx:87` says "all ten bells"; `docs/adr/0008-the-completion-moment-carries-no-ask.md:73` says "all twelve tool home screens". The registry holds **eleven** (`src/features/notifications/registry.ts:4-15`) and the bell has **eleven** call sites (every `targetKey:` caller of `ModuleHomeHeader`: act, breathing, cbt, dbt, gratitude, grounding, habits, journal, meditation, mood, sleep).
- The map cites `docs/modules/cbt.md:83` for the stale "native reminders are local schedules" line; it is at `docs/modules/cbt.md:89`.
- Two hand-written target lists have **already drifted** at eleven: `test/integration/db-functions.integration.test.ts:129-140` and `scripts/seed-demo-data.mjs:5777-5787` both list ten keys and omit `dbt`, despite the seed comment saying "a new tool's column has to be added here on purpose". Neither fails when a target is missing.
- The suppression check never reads a `*_offset_minutes` column. It is **viewer-local at send time** (`startOfZonedDay(now, channelTz)`, `supabase/functions/_shared/web-reminders.ts:509,530-536`), not captured-day, for every target today. The captured-day/viewer-local split in #1990 is a fact about the _tables_, not about this check.

Facts that follow:

- **Cost.** Today a due target costs 1 round trip for eight targets, 7 for ACT and 6 for DBT (`index.ts:93-119`, sequential `limit 1`, early exit). An "any tool" union costs up to **21 sequential round trips per channel row per due tick** when the person has used nothing — the case suppression exists to detect — i.e. three times ACT's worst case, run once for the web row and again for each native token (`index.ts:295-315,478-493`). No RPC or view answers "any row today" in one call; each `ActivityWindow` is one PostgREST query.
- **Frame.** The union inherits the current check's frame: viewer-local at send time, anchored to the channel's zone (`index.ts:305-306,483-484`), ignoring the 15 tables that carry a captured-day offset and matching the 7 ACT tables that have none. `habit_logs` is the one captured-day source. So the answer would be "wrote a row today in the sender's zone", not "did something on the day the person experienced".
- **What it is not.** It is "any of the 21 tables the eleven targets already name", not "used the app". CBT's activities tool writes `activity_logs` (`20260731120000_activity_occurrence_offsets.sql:31-35`) and is in no target's sources; opening the app or reading a learn page writes nothing here. No server-side "opened today" signal exists: the only candidate column, `auth.users.last_sign_in_at` (read by `20260826010000_guest_dormancy_cleanup.sql:44`), records a sign-in, not a launch.
- **The routines precedent.** Routines skip suppression precisely because "complete today" would mean reading every step tool's table (`web-reminders.ts:547-549`); they dedupe once per day per channel through `last_routine_reminder_keys` (`:683-696`) and nothing else. A general target with no `activitySources` cannot exist under the current type (`:175`) — the routine path is a different code path (per-row fields, a jsonb stamp map), not a configuration of `TARGET_CONFIGS`.

**Verdict on the ticket's question:** "any tool used today" is computable, but not cheaply and not honestly — it costs up to 21 sequential reads per channel row on exactly the tick that matters, and it measures tool rows in the sender's zone rather than app use. The routines precedent (no suppression, one-per-day dedup only) is the only shape the code already has for a reminder with nothing to read.

## Tally

Twenty-nine rows. **Six assume a tool**: the registry's practice gate, the registry's Favourites-catalogue destination lock, the `TargetConfig.activitySources` non-empty type (with its `web-reminders.test.ts` pin), `activityWindowsForTarget` as written, the routine overlap detector's tool identity, and `CONTEXT.md`'s glossary definitions. Everything else takes a new prefix and a chosen url, default hour and copy; `enableTargetPatch` writes `reminder_consent`, so analytics §8 counts a general enable unchanged.
